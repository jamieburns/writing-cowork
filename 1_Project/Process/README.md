# Process

What we do, how we do it, why we do it, and when (if it matters). Two docs live here so far:

- `dev-workflow-and-release.md` — the plugin dev cycle, release checklist, and Cowork-side refresh procedure.
- `tool-lane-discipline.md` — which tool to use for which kind of filesystem/git operation, and why.

Both are distilled from `1_Project/Memory/` entries. When a memory matures into a repeatable procedure, it should get (or update) a doc here, with the memory file kept as the origin record.

`lift/README.md` (the staged vault-setup procedure for new end-user projects) stays at the repo root — it's part of the shipped product (`0_Product`), not this dev project's own process.
